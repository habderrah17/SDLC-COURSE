# tools/ — الفحوص الآلية للكورس (Course checks)

كل ما في هذا المجلّد يعمل بـ Node ≥ 22 بعد `npm ci` من جذر المستودع، ويعمل نفسه في CI (`.github/workflows/ci.yml`).

| الأمر | ماذا يفحص |
|---|---|
| `npm run check:structure` | كل `level-*/module-*.md`: السطر الأول `# Module N.N — …`، السطر الثاني `## English subtitle`، الأقسام **1–19** بالترتيب وبعناوينها القياسية، سطر "قبل أن تتعلم هذا، يجب أن تفهم"، وجدول `المصطلحات`. وجود `README.md` و`checkpoint-N.md` لكل مستوى. الاستثناءات والعناوين المقبولة في `structure.config.json`. |
| `npm run check:links` | كل رابط نسبي في كل ملف `.md` (خارج كتل الكود) يُشير إلى ملف موجود. |
| `npm run check:glossary` | `glossary.md`: 4 أعمدة، مرتّب بالإنجليزية، بلا تكرار، وكل وسم `Lx-My` يُشير إلى وحدة موجودة. |
| `npm run check:mermaid` | كل كتلة `mermaid` تُحلَّل بمحلّل Mermaid الحقيقي. |
| `npm run check` | الأربعة أعلاه. |
| `npm run examples -- 8.7` | يستخرج أمثلة وحدة واحدة ويُترجمها (`tsc` بـ `strict` + `noUncheckedIndexedAccess`) ويُشغّل اختباراتها (`node:test`). |
| `npm run examples:all` | كل الوحدات والمشاريع التي فيها أمثلة، **ما عدا** ما يحتاج PostgreSQL. |
| `npm run examples:db` | الكل، بما فيه وحدات قاعدة البيانات (يحتاج `DATABASE_URL`، مثلًا `postgres://app:app@127.0.0.1:5432/store` — المستخدم يجب أن يكون superuser لأن بعض الاختبارات تُنشئ أدوارًا). **تحذير:** يُعيد إنشاء schema `public` في تلك القاعدة قبل كل وحدة. |
| `… --typecheck-only` | ترجمة فقط بلا تشغيل الاختبارات. |

## اتفاقية الأمثلة القابلة للتشغيل

- كتلة `typescript` سطرها الأول `// src/<path>.ts` تُستخرج إلى ملف بذلك المسار. يجوز أن يلي المسار شرح بعد مسافة أو `—`.
- كتلة واحدة قد تحوي عدّة ملفات: كل سطر `// src/…` في بداية سطر **بعد سطر فارغ** يبدأ ملفًا جديدًا.
- رأس يحوي `❌` = عرض متعمّد لكود لا يُترجَم؛ لا يُستخرج.
- كتلة `sql` سطرها الأول `-- src/<path>.sql` أو `-- migrations/<path>.sql` تُستخرج أيضًا (مخطّطات تُقرأ وقت التشغيل).
- الاختبارات: ملفات `*.test.ts` بـ `node:test` و`node:assert/strict`. وحدات قاعدة البيانات تقرأ `process.env.DATABASE_URL` وتُنشئ ما تحتاجه من مخطّط بنفسها (idempotent).
- وحدة تبني على ملفات وحدة سابقة (مثل `db.ts` من M3.10) تُسجَّل في `examples.config.json → dependsOn`.
- الملفات المستخرجة تذهب إلى `.examples/` (مُتجاهَل في git).
